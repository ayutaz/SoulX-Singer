# 日本語対応の分析

## 現状

SoulX-Singerは現在、中国語（普通話）、英語、広東語の3言語に対応。
日本語（`ja_`）の音素はphone_set.jsonに一切含まれておらず、G2P・ASRも未対応。

## 日本語対応に必要な作業

### 1. 前処理パイプラインの拡張

#### 1.1 日本語G2P（書記素→音素変換）

日本語テキストを音素列に変換するモジュールの追加が必要。

**候補ライブラリ:**

| ライブラリ | 特徴 |
|-----------|------|
| `pyopenjtalk` | Open JTalkベース。日本語TTS向けの標準的なG2P。音素+アクセント情報 |
| `cutlet` | 日本語→ローマ字変換。簡易的だが音素としては不十分 |
| `espeak-ng` + `phonemizer` | 多言語対応。IPAベースの音素出力 |
| `julius` | 日本語音声認識エンジン由来の音素体系 |

**推奨: `pyopenjtalk`**
- 日本語TTS/SVSで最も広く使われている
- 音素体系が明確（母音5種 + 子音 + 特殊音素）
- アクセント・イントネーション情報も取得可能

#### 1.2 日本語ASR（歌詞文字起こし）

歌声から歌詞テキストを認識するASRモデルの追加。

**候補モデル:**

| モデル | 特徴 |
|--------|------|
| OpenAI Whisper (large-v3) | 多言語対応、日本語性能良好。歌声認識の精度は要検証 |
| ReazonSpeech | 日本語特化ASR。高精度だが歌声への対応は未検証 |
| NVIDIA Parakeet (日本語版) | 既存の英語版と同じフレームワーク |
| FunASR (日本語対応) | 既存の中国語版と同じフレームワーク |

**推奨: Whisper**
- 歌声を含む多様な音声への汎化性能が高い
- セットアップが容易
- 多言語対応で他言語との統合もスムーズ

### 2. 音素辞書の拡張

#### 2.1 日本語音素の定義

`pyopenjtalk` の音素体系をベースにした場合:

**母音 (5種):**
```
ja_a, ja_i, ja_u, ja_e, ja_o
```

**子音 (約15種):**
```
ja_k, ja_s, ja_t, ja_n, ja_h, ja_m, ja_y, ja_r, ja_w,
ja_g, ja_z, ja_d, ja_b, ja_p, ja_f
```

**特殊音素:**
```
ja_N    (撥音「ん」)
ja_cl   (促音「っ」)
ja_q    (長音)
ja_ky, ja_sh, ja_ch, ja_ts, ja_ny, ja_hy, ja_my, ja_ry,
ja_gy, ja_j, ja_by, ja_py  (拗音・特殊子音)
```

**概算: 30〜50音素**

#### 2.2 phone_set.json への追加

### 3. モデルの学習（最大の課題）

音素辞書とEmbeddingを拡張しただけでは、モデルは日本語音素に対応した歌声を生成できない。
**日本語歌声データでの学習（ファインチューニング）が必須。**

詳細は `03_training_analysis.md` を参照。

## 必要な日本語歌声データの要件

### 最低要件

| 項目 | 要件 |
|------|------|
| データ量 | 最低数十時間（理想は数百時間以上） |
| サンプルレート | 24kHz以上（モデルは24kHzで動作） |
| 品質 | クリーンなボーカル（伴奏分離済みが望ましい） |
| アノテーション | 歌詞テキスト（タイムスタンプ付きが理想） |
| 多様性 | 複数歌手、複数ジャンル |

### アノテーションの形式

前処理パイプラインを使えば、以下を自動生成可能:
- F0コンター
- VADセグメント
- ノートピッチ・デュレーション（ROSVOT）

ただし歌詞の文字起こしはASRの精度に依存するため、手動修正が必要な場合がある。

### データ準備フロー

```
日本語歌声音声ファイル群
  │
  ├─ 前処理パイプライン（日本語対応版）
  │   → ボーカル分離、F0抽出、VAD、歌詞認識、ノート転写
  │
  ├─ 手動修正（必要に応じて）
  │   → MIDIエディタで歌詞・ピッチ・タイミングを修正
  │
  └─ メタデータJSON（学習用）
```

## 代替アプローチ（学習なし）

モデルの再学習が困難な場合の代替案:

### 案1: ローマ字→英語音素マッピング

日本語の歌詞をローマ字に変換し、英語の音素にマッピング。

```
例: "さくら" → "sa ku ra" → en_S + en_AA1 / en_K + en_UW1 / en_R + en_AA1
```

**メリット:** 学習不要、即座に試せる
**デメリット:** 発音の正確性が低い、日本語特有の音韻（撥音、促音、長音）が表現困難

### 案2: 中国語音素マッピング

日本語の音韻を類似する中国語音素にマッピング。

**メリット:** 一部の音韻が近い（特に漢字の音読み）
**デメリット:** 声調体系が異なる、不自然になる可能性が高い

### 評価

いずれの代替案も品質は保証できず、**ファインチューニングが最も確実なアプローチ**。
